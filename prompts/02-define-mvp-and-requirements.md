# Prompt 02 — Define MVP and requirements (NO CODE)

Read the approved product brief, domain research and open-question log. Do not invent requirements or implement code.

Create/update:
- `docs/02-mvp-scope.md`
- `docs/04-requirements.md`
- `docs/05-business-rules.md`

For each feature, state user value, actor, trigger, preconditions, main flow, alternate/failure behavior, priority and release. Use stable IDs (`FR`, `BR`, `AC`). Write acceptance criteria as Given/When/Then and make them objectively testable.

Use `MUST/SHOULD/COULD/OUT OF SCOPE` or MoSCoW. Explicitly identify contradictions and requirements that affect money, state transitions, data history, permissions, concurrent updates, printer behavior, network failures and recovery.

Separate:
- confirmed stakeholder facts;
- external facts, with source URL and date checked;
- assumptions requiring approval;
- suggestions from you.

Do not change a decision marked `DECIDED` silently. If new evidence contradicts it, propose a change with impact and wait for owner approval. Finish with a Gate A/Gate B checklist and a list of unresolved blockers. No code.
